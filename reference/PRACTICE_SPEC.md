# 練習機能の仕様

MegaminxImageEditor の `reference/PRACTICE_SPEC.md` を VisualCube Editor（3x3x3）用に書き直したもの。コードと食い違うときはコードを正とする。

## 目的
スクランブルで手元のキューブを崩し、解くタイムを測って、PLL・OLL・COLL・ZBLL を覚えているかを確かめる。
目安の時間（しきい値）以内に解けたケースは自動で「習得済み」、超えた・解けなかったケースは「練習中」にする。

## データ
- 元データ：`data/pll/scrambles.json`・`data/oll/scrambles.json`・`data/coll/scrambles.json`・`data/zbll/scrambles.json`（`{ ケース名: [スクランブル 20 本] }`。キーは `algs_info.json` の `name`）
- 生成：`node tools/gen-scrambles.js`（json を作る。ケースの状態にランダムな AUF を足したものを `js/cube-solver.js` で解き、その逆手順をスクランブルにする。種は固定）
  → `node tools/build-scrambles.js`（`js/pll-scrambles.js`・`js/oll-scrambles.js`・`js/coll-scrambles.js` = `window.PLL_SCRAMBLES = { "Aa": [...] }` を作る）
  - 各スクランブルで崩した状態が、そのケースになるかを確かめる（`js/case-check.js` の `fitSetup`。`test/scrambles.test.js` が全件を確かめる）
  - PLL・OLL・COLL のデータ（`algs_info.json`）を変えたら作り直す
  - ZBLL のスクランブルは用意されたもの（ケースごとに 4〜20 本）を使い、作り直さない（`gen-scrambles.js` の対象外。`build-scrambles.js` で確かめて `js/zbll-scrambles.js` を作る）
  - 練習ページだけが読み込む（エディタ・一覧は重くならない）

## 練習ページ（`practice.html`・`js/practice.js`・`css/practice.css`）
- 設定
  - 種類：PLL / OLL / COLL / ZBLL / 通し（見出し「練習」の横に置き、下の設定の行を1行に収める）
  - グループ：「すべてのグループ」または選んだグループ（例：`Dot, Square`）。押すとグループのボタンが並ぶ欄が開き、押したグループだけを出題する（1つも選んでいなければすべて。「選択を解除」で戻す）。グループのボタンにマウスを乗せると説明とケースの数が出る。PLL・OLL・COLL・ZBLL それぞれで覚えておく
    - ZBLL の小グループ順は2段：OCLL を1つ選び、その中の小グループで絞る（一覧と同じ決まり。`reference/ZBLL_SPEC.md`）
  - 対象：未習得 / 練習中 / 習得済み / すべて（それぞれ件数付き。グループで絞った中の件数）
  - 習得の目安：2秒 / 3秒 / 5秒 / 8秒（既定は 3秒）、または入力欄に数値（1〜120 秒）。入力した秒数はボタンには足さず、入力欄を強調する。PLL・OLL・COLL・ZBLL で別々に持ち、設定欄には今の種類の目安を出す（例：PLL は 5 秒、OLL は 2 秒）。判定・記録のページのグラフの破線・苦手順の並びも、その種類の目安を使う（`Progress.thresholdOf`）
  - 出題：苦手を多めに / ランダム（PLL・OLL・COLL・ZBLL 共通。既定は苦手を多めに）。苦手を多めにでは苦手なケースほど出やすくし（下の「出題」）、ランダムではどのケースも同じ確率。変えても今の問題はそのまま
  - グループを選ぶ欄で「グループ順 / 覚える順」（OLL は「番号順 / 覚える順」）を切り替える（一覧と共通の `list-filter` の `<set>Order`）。覚える順では段階（PLL は U〜N、OLL は A〜M。Cube Voyage 準拠）で選ぶ（`prefs.groups['<set>-stage']`）。
    OLL の番号順ではグループを選ばない（すべてから出題。前に選んだ OLL のグループは使わない）。OLL の範囲（No Dot / Dot）は無い（Megaminx 版にだけある）
- 出題：対象に当てはまるケースから選ぶ（直前と同じケースは避ける）。設定の出題が「苦手を多めに」なら、どの対象でも苦手なケースほど出やすくする（苦手な順に出すのではなく、確率に差をつける。習得済みでも危ういケースが多めに出る）：苦手の度合いは記録のページの苦手順と同じ（`Progress.weakScores`：その種類の直近 10 回の平均、解けなかった回はその種類の習得の目安の 2 倍、回数の少ないケースは全体の平均で 2 回解いたものとして足す）で、重みは（度合い ÷ 習得の目安）を 0.5〜3 に収めて 2 乗（0.25〜9。`Progress.pickWeighted` で選ぶ）。まだ解いていないケースは解けなかったのと同じ扱い（目安の 2 倍 → 重み 4）にして、苦手なケースと同じくらい出るようにする（試算：「すべて」で全ケースが一通り出るまで、PLL 21 ケースは約 27 問〔ランダムでは約 76 問〕、OLL 57 ケースは約 81 問〔約 255 問〕、COLL 40 ケースは約 56 問〔約 164 問〕。記録の無い状態から、出たケースは目安以内で解けたとして 400 回試した平均）。記録が1つも無ければすべて同じ確率。
  選んだケースのスクランブル 20 本からランダムに選び、**そのまま出す**
  （ランダムな AUF 込みで作ってあるので、出題のときに AUF は足さない）。ケースの名前と画像は解き終わるまで出さない。対象が0件なら「対象のケースがありません」
- タイマー
  - スペースキーを押した瞬間にスタート（画面ではタイマーの数字をタップした瞬間）。計測中は数字を青にする
  - 計測中は何かのキー（画面ではどこかをタップ）でストップ。Esc は中止（記録せず、同じスクランブルのまま）
  - ボタンは状態で出し分ける（行の高さはいつも同じ）：スタート前（止めたあとも）は「スキップ」「ヒント」、計測中は「解けなかった」「ヒント」「中止」、通しのインスペクション中は「中止」だけ（通しでは解けなかった・スキップ・ヒントは出さない）
  - キーボードのショートカット：S＝スキップ、H＝ヒント、D＝解けなかった、Esc＝中止。そのボタンが出ているときだけ効き、計測中の H・D は止める操作にしない（ほかのキーは今までどおり止める）。日本語入力がオンでも効くよう、キーの位置（`e.code`）で見る。ボタンには「スキップ (S)」のようにキーを添える（マウスが使える画面だけ。`@media (hover: hover) and (pointer: fine)`）
  - 「スキップ」：記録せずに次の問題へ（習得済みにはならない）。「中止」：Esc と同じく記録せず、同じスクランブルのまま 0.00 に戻す（スマホには Esc が無いため）。計測中に「解けなかった」を押すと、タイムを記録せずに練習中にする（押した瞬間に DNF にする。ボタンは計測中だけ出すので、止めるとすぐ隠れて離したときのクリックが届かないため。0.00 に戻してすぐ DNF を書くので、間に 0.00 は見えない）
  - 計測中に「ヒント」を押しても止まらない（計測を続けたままヒントを出す）
  - マウス・タップで押したボタン（解けなかった・スキップ・ヒント・結果の取り消すなど）からはフォーカスを外す（そのあと Esc などを押したときに、ボタンが塗りつぶしの見た目にならないように）。キーボードで押したときは外さない
  - スタートから 0.5 秒は止まらない（スタートした直後に続けてキーを押して、止めてしまわないように。キー・タップとも。Esc の中止・「解けなかった」「スキップ」は効く）。通しも同じ
  - 止めてから 2 秒はスタートしない（止めた直後に続けてキーを押して、次の計測を始めてしまわないように）。その間はタイマーの数字を赤にする（目立つように）。通しの長押し・インスペクションも同じ。ボタン（解けなかった・スキップなど）は 0.4 秒のあとは押せる
  - キーの押しっぱなしによる繰り返しは無視する（スタートしたスペースを押し続けても止まらない）
  - 計測中もスクランブルは出したまま（通しも同じ）。操作の説明は隠す（ヒントは出したまま）。止めたタップでそのままボタンを押さないよう、止めてから 0.4 秒はボタンを無視する
  - 止めたあと（「解けなかった」も）はタイムを 0.00 に戻さず、次の計測が始まるまで出したままにする（「解けなかった」は `DNF`）。
    タイマーのすぐ上に、解いたケース（`PLL Aa`・`OLL 27`）を出す。この行は空のときも高さを取っておき、出し入れでタイマーが動かないようにする。
    結果の「取り消す」を押したら 0.00 に戻し、ケースの名前も消す。「スキップ」・設定の変更でも 0.00 に戻す
- **ヒント**（スタート前・計測中に押せる。インスペクション中は出さない）：ケースの名前と、解く手順（自分の手順があればそれ）の最初の3手を出す。もう一度押す（ボタンは「ヒントを隠す」になる）と消す。ヒントを見た問題は、目安以内で解けても練習中にし、タイムを最近の記録に入れない
- 判定（`js/progress.js` の `judge`）：目安以内 → 習得済み、超えた → 練習中。「解けなかった」→ 練習中（タイムは DNF）。「スキップ」は記録せず次へ
- 結果：タイム、判定（例：「✓ 習得済み（3秒以内）」）、**取り消す**（直前の判定とタイムを戻す）、ケースの画像・名前・手順（自分の手順があればそれ）、そのケースの最近のベスト・平均
- 直近の記録：このページを開いてからの結果を最大12件（ケース名とタイム、習得済みは緑・練習中は琥珀）
- 判定したら次の問題（スクランブル）をすぐ出す（結果は前の問題のもの）
- 画像は上面図（`js/cube-draw.js`。srVisualizer の Plan 表示）。配色は一覧と同じ（`Progress.displaySettings`）

## 保存（`js/store.js` 経由。ログイン中はクラウドにも）
- 習得状況：一覧と同じ `progress` を書き換える（`js/progress.js`。一覧と練習で共通）
- `practice`：`{ set, filter, weighted（出題が苦手を多めにか。無ければ true、false はランダム）, thresholds: { pll: 秒, oll: 秒, coll: 秒 }（以前の共通の threshold があれば、無い種類の目安に使う）, groups: { pll: ["Edges only"], oll: [] }, stats: { 記録のページの表示 }, log: [日時付きの記録], times: { pll: { "Aa": [最近のタイム(秒) 新しい順 最大10件] }, oll: {…} }, full: { 通しの設定と記録 } }`
- URL `?set=oll&filter=new` で設定の初期値を指定できる（その値で保存し直す）。`&groups=Dot,Square` で出題するグループ、`&case=Aa` で最初の1問のケース

## ほかのページ
- 全ページのナビバーに「練習 / Practice」
- PLL・OLL・COLL・ZBLL 一覧の上部に **練習する** ボタン：今の絞り込み・選んだグループのまま `/practice?set=…&filter=…&groups=…` を開く。練習ページは URL の種類・絞り込みを保存してから使う（保存済みの前回の値で上書きされないように）
  - `groups` は一覧で選んだグループ。空ならすべて。練習ページはその選択で保存し直す（一覧で何も選んでいなければ、練習ページの選択も外れる）

## 記録（`stats.html`・`js/stats.js`・`css/stats.css`）
- 判定のたびに `practice.log` に `{ at: 日時(ms), set, name, sec(null=解けなかった), status, hint }` を足す（新しい順、PLL と OLL を合わせて最大 2000 件。「取り消す」でその1件も消す）。集計は `js/progress.js` の `addLog`・`summarize`・`daily`・`perCase`
- ナビバーの「記録 / Stats」、練習ページの「すべての記録を見る」（`/stats?set=oll` のように今の種類を渡す）から開く
- 種類（PLL / OLL / COLL / ZBLL / 通し）・期間（7日 / 30日 / すべて）で絞る（`practice.stats` に保存）。種類は練習ページと共通（`practice.set`）で、練習と記録を行き来しても選んでいた種類のまま開く（どちらのページで変えても、もう一方に引き継ぐ）
- 集計のカード：練習回数、平均（とベスト）、解けなかった回数、習得済みの数（今の習得状況）
- タイムの推移：横軸＝期間内の1回ごとの記録（古い順、1 から数える）、縦軸＝タイム。ライブラリを使わず SVG で描く（表示する幅で描く）
  - 通し：点＝1回のタイム、線＝その時点の ao5・ao12（`Progress.rollingAverages`。期間より前の記録も使って出す。DNF・回数が足りないところは線が途切れる）
  - PLL・OLL・COLL・ZBLL：ao は出さず、1回ごとのタイムを線で結ぶ（解けなかったところは飛ばして前後を結ぶ）。点の色＝判定（習得済み＝緑、練習中＝琥珀）。破線＝その種類の今の習得の目安
  - DNF は上の端に ×。縦軸の上は ao5・ao12 の最大と1回のタイムの 95% 点の大きい方までにし、それより遅い点は上の端に △（外れ値で線がつぶれないように）
  - マウス・タッチで、いちばん近い記録の縦線と、何回目・日時・タイム（PLL・OLL・COLL・ZBLL はケース名も、通しは ao5・ao12 も）を出す
- ケースごとの表：画像・ケース・グループ・習得状況・最近・回数（解けなかった回数）・ベスト・平均・最後に練習した日。見出しを押すと並べ替え。
  - 表の上の切り替えで並びを選ぶ：**苦手順**（既定）/ **グループ順**（OLL は **番号順**）/ **覚える順**（COLL は覚える順のデータが無いので出ない。ZBLL は「小グループ順」だけで、OCLL ごとは小グループ順と同じ並びなので出さない）。選んだ並びは `practice.stats.sort`・`desc` に保存（`sortV: 2`。苦手順を足す前に保存した並びは使わず苦手順にする）。見出しで別の列を選んだら、切り替えはどれも選ばれていない状態
  - 最近：期間内の直近 10 回の平均（解けた回だけ。解けなかった回があれば赤で「DNF n」を添える。全部解けなかったら「DNF」）。3 回未満は薄く出す（参考値）。`Progress.recentPerCase`
  - 並びのボタンにはマウスを乗せると説明を出す（苦手順・グループ順〔OLL は番号順〕・覚える順。練習ページの並びの切り替えも同じ）
  - 苦手順：最近の遅い順。並べるときは解けなかった回を習得の目安の 2 倍のタイムとして数える（失敗の多いケースが上に来るように）。回数の少ないケースがたまたまの1回で上に来ないよう、全体の平均のタイムで 2 回解いたものとして足した平均で並べる（表に出すのは足す前の平均）
  - グループ順：データに出てくるグループの順（3x3 のグループ名は A〜Z の順ではないので、名前では並べない）、同じグループの中はデータの順
  - ケースを押すと、そのケースを最初に出題する練習ページ（`/practice?set=…&case=…`）を開く
- PLL・OLL・COLL・ZBLL の表は「ケースごと / 記録の一覧」を切り替えられる（`practice.stats.tab` に保存）。記録の一覧は期間内の記録を新しい順に、日時・ケース・タイム（解けなかった）・判定（ヒントを見たものは「ヒント」）・×
- 記録の削除（PLL・OLL・COLL・ZBLL の記録の一覧、通しの記録の一覧）：個別は各行の ×、一括はチェックで選んで「選択した記録を削除（n）」→ 確認 →「削除する」。削除の行の右端の「すべての記録を削除」（目立たない小さなグレーの文字のリンク。記録が無ければ出さない）は、表示中の種類（PLL / OLL / COLL / ZBLL / 通し）の記録を期間に関係なくすべて消す。押すと「PLL のすべての記録（n 件）を削除しますか？…」と「すべて削除する」「キャンセル」を出す（最初のフォーカスはキャンセル）。どれも削除のあとに「元に戻す」。PLL・OLL・COLL・ZBLL で消すのは `practice.log` のその種類の記録だけで、習得状況と練習ページの最近のタイム（`practice.times`）は変えない。種類・表を切り替えたら選択を外す
  - 色：普段出ているボタン・リンク（解けなかった・選択した記録を削除・すべての記録を削除・行の ×）は周りと同じグレー。赤くするのは、確認のあとに押す「削除する」「すべて削除する」だけ（一覧の「未習得に戻す」、プライバシーポリシーの「削除する」も同じ）
- 記録の一覧（PLL・OLL・COLL・ZBLL・通し）のページ分け：1ページ 50 件（新しい順）。51 件以上あるときだけ、表の下に「215 件中 51〜100 件目」と「‹ 前へ 1 2 3 4 5 次へ ›」を出す（8 ページ以上のときは最初・最後・今の前後だけを出し、あいだは「…」）。見出しのチェック（スマホは削除のバーの「すべて」）は今のページの記録だけを選ぶ・外す。選んだ記録はページを移っても選んだまま。種類・期間・表を変えたら1ページ目に戻す。削除で件数が減ったら最後のページに収める。下のページ送りで移ったときは表の頭までスクロールを戻す。ページは保存しない
- 別のタブで練習したら、記録のページにも反映する（storage イベント）

## 通し（Full solve）
- 練習ページの種類「PLL | OLL | 通し」の「通し」で、3x3x3 を通しで解くタイムを測る。記録のページにも「通し」
- スクランブル（`js/wca-scramble.js`・`js/cube-solver.js`）：WCA と同じ random-state。一様ランダムな状態を作り、two-phase ソルバで解いた逆手順を出す（1 行、20 手前後。2 手未満で揃う状態は作り直す）
  - 次の 1 本を先に作っておく（`WcaScramble.prepare`）。ページを開いて最初の 1 本だけは、ソルバの表の準備（PC の Chrome で約 0.4 秒）が終わるまで「スクランブルを作成中…」と出し、タイマーを押せなくする。2 本目からは待たない（1 本 平均 約 10 ms）
  - 幅が足りなければ手の区切りで折り返す（`css/common.css` の `.scramble-line`）
- 設定：インスペクション（15秒）あり / なし。対象・グループ・目安・ヒントは出さない
- タイマー
  - **長押しして離すとスタート**：スペース（スマホはタイマー）を 0.3 秒押すと準備完了（数字が赤 → 緑）、離した瞬間にスタート。短く押しただけでは始まらない。ストップは任意のキー・タップ（PLL・OLL・COLL・ZBLL と同じ）
  - インスペクションあり：スペース（タップ）で 15 秒のカウントダウン（残り秒数）。8 秒・12 秒で色が変わる。カウントダウン中にスペースを長押しして離すと計測開始。15 秒を超えて 17 秒までに始めたら +2、17 秒を超えたら DNF（WCA の規則どおり）。インスペクション中の Esc は中止
