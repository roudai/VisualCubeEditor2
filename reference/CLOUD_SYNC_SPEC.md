# ログインとクラウド保存の仕様

MegaminxImageEditor の `reference/CLOUD_SYNC_SPEC.md` を VisualCube Editor 用に書き直したもの。仕組みは同じで、アプリ名・保存する名前・ドメインが違う。
コードと食い違うときはコードを正とする。

## 目的
配色・画像の設定、習得状況、一覧の絞り込み、自分の手順、練習の設定と記録、言語を、ログインしたアカウントに保存し、どの端末・ブラウザでも同じ状態で使えるようにする。
ログインしなくても今までどおりブラウザ（localStorage）だけで使える。

## 構成
- サイトは静的ページ（`visualcube.roudai.net`）のまま。Firebase（Authentication + Firestore）をブラウザの JS から直接使う（SDK は gstatic の CDN から ES モジュールで読み込む。バージョン固定）
- ログイン：Google / Facebook / GitHub（ポップアップ。メニューもこの順）
  - ポップアップが開けない・この環境ではログインできない（`auth/popup-blocked`・`auth/operation-not-supported-in-this-environment`・`auth/web-storage-unsupported`）ときは、「ログインできませんでした」の代わりに「アプリの中のブラウザではログインできないことがあります。Chrome や Safari で開いてください。」と「ページの URL をコピー」のボタンをメニューに出す（独自の WebView のアプリ内ブラウザ向け。コピーできない環境では URL を選んだ状態の欄を出し、メニューは閉じない）。端末の判定で最初から案内することはしない（Android の X のアプリの中のブラウザは中身が Chrome で、Google でもログインでき、Chrome と同じアカウント・保存になるため）。MegaminxImageEditor 380f89b
- 保存先：Firestore の `users/{uid}/apps/visualcube-editor` の1文書 `{ json, savedAt }`。`json` は下の snapshot を JSON にした文字列
  - PLL・OLL・COLL・ZBLL の練習の記録（`practice.log`。各最大 5000 件）は 1 文書（50 万文字未満）に入らないので、種類ごとの文書 `users/{uid}/apps/visualcube-editor-log-pll`・`-log-oll`・`-log-coll`・`-log-zbll`（同じ `{ json, savedAt }`）に分ける（`Store.toCloud`・`fromCloud`。Megaminx Image Editor 865ec44 と同じ仕組み）
    - 種類ごとの文書の `json` は `{ rows: [[日時, ケース, タイム（null＝解けなかった）, 判定（0 未習得・1 練習中・2 習得済み）, 1（ヒントを見たときだけ）], …] }`（新しい順。1 件 約 30 文字で 5000 件 約 16 万文字。48 万文字を超えるときは古い記録を捨てる）
    - ソルブの記録（`practice.full.log`。最大 5000 件）も、本体の余裕のために `-log-full` に分ける。`json` は `{ rows: [[日時, タイム, スクランブル（短い形。無ければ null）, ペナルティ（'+2'・'DNF'。無ければ付けない）], …] }`（1 件 約 45 文字で 5000 件 約 23 万文字。Megaminx Image Editor 1b04634 と同じ仕組み）
    - LL の記録（`practice.ll.log`。最大 5000 件）も `-log-ll` に分ける。`json` は `{ rows: [[日時, タイム（DNF は null）, OLL の名前, PLL の名前], …] }`（1 件 約 30 文字で 5000 件 約 15 万文字）。本体に `llSplit: true` を付け、読むときは `llSplit` のときだけ `-log-ll` を読む（無ければ本体の記録）。Firestore のルールは変えなくてよい（`logDoc()` が `-log-ll` も許す。Megaminx Image Editor 976f502 と同じ仕組み）
    - 本体の `json` は記録を抜いた snapshot（ソルブはインスペクションなどの設定だけ残す）に `logsSplit: true`・`fullSplit: true` を付けたもの。読むときは `logsSplit` があれば PLL・OLL・COLL・ZBLL の文書の記録を戻し、`fullSplit` があれば `-log-full` からソルブの記録を戻す（`-log-full` は `fullSplit` のときだけ読む）。無ければ（以前の形・古いページが書いた本体）本体の記録をそのまま使う
    - 書くときは、中身が変わった種類ごとの文書を先に書いてから本体を書く（1 回の練習で書くのは本体とその種類の文書だけ）
    - 種類ごとの文書に書けなかったとき（Firebase コンソールのルールが古いなど）は、記録を本体に入れた以前の形（PLL・OLL・COLL・ZBLL は合わせて、ソルブはそれぞれ最新 2000 件）で本体だけ書き、保存の状態はエラーにする（ほかの変更は失わない）
- Firebase プロジェクト（`roudainet-cube-tools`）とアカウントは Megaminx Image Editor と共通。各アプリは `users/{uid}/apps/<アプリ名>` に保存し、互いの保存先はぶつからない
  - ほかのアプリも同じ形（`{ json, savedAt }`）で保存すれば、`firestore.rules` は変えなくてよい
  - localStorage のキーの頭は `visualcube-editor:`（`Store.PREFIX`）。Megaminx Image Editor（`megaminx-image-editor:`）と同じドメインに置いても混ざらない
- `firestore.rules`：本人の `users/{uid}/apps/{アプリ名}` だけ読み書きでき、中身は `json`（50万文字未満の文字列）と `savedAt` だけ（プロジェクト共通のルール）。作る・書き換えるのはルールの `appIds()` に書いたアプリ名（`megaminx-image-editor`・`visualcube-editor`）と、その練習の記録の文書 `<アプリ名>-log-<種類>`（種類は英小文字・数字の 1〜12 文字。`logDoc()`）だけ。種類を増やしてもルールは変えなくてよい。アプリを増やしたら `appIds()` と `logDoc()` の両方に名前を足して Firebase コンソールに貼り直す。
  このリポジトリの `firestore.rules` は Megaminx Image Editor のものと同じ内容（どちらか片方を直したら、もう片方も同じ内容にする）

## 保存の窓口（`js/store.js`）
- エディタ・一覧・練習・記録のページの保存はすべて `Store.get(name)` / `Store.set(name, value)` を通す（localStorage のキーは `visualcube-editor:<name>`）
- 名前：`settings`（配色・画像の設定）、`progress`（習得状況。`{ pll: {…}, oll: {…}, coll: {…}, zbll: {…} }`）、`list-filter`（一覧の絞り込み）、`custom-algs`（自分の手順）、`practice`（練習の設定と記録）、`lang`（言語）
  - `settings` = `{ preset, faceColors: { U, R, F, D, L, B }, beforeOll, customScheme, imageSize, border, bgColor, bg }`
    （`border` はエディタの Cube Color、`bgColor`・`bg` は Background Color と Background。パズルの種類・表示・マスク・回転・矢印は保存しない）
- `set` は値が変わったときだけ、名前ごとの更新時刻（`visualcube-editor:updated`）を記録し、`store-change` を通知する
- `snapshot()` = `{ data: { name: value }, updated: { name: 時刻 } }`

## ログインしたときの合わせ方（`Store.resolveLogin`）
- 合算はしない（以前は、ログインせずに使った手元の内容をアカウントと合わせていたが、練習の記録は新しく更新された方を丸ごと使うため、ログイン前に数件練習しただけでアカウントの記録が消えることがあった）
- 手元のデータがどのアカウントのものかを `visualcube-editor:synced-uid` に、ログインしたままかを `visualcube-editor:session`（ログイン中 `in`、ログアウトの状態が分かったら `out`）に覚えておき、次のように決める
  - **新しくログインした**（`session` が `out`）：
    - アカウントにデータがあれば、アカウントの内容で手元を上書きする。ログイン前にこのブラウザで使った内容（習得状況・練習の記録など）は捨てる
    - アカウントが空なら（初めてのログイン・アカウントを削除して作り直した）、手元の内容をそのままアカウントに入れる。ただし手元が別のアカウントのもの（`synced-uid` が別）なら持ち込まず初期状態
  - **ログインしたままページを開いた**（`session` が `out` でなく、`synced-uid` が同じ）：下の `Store.merge`（名前ごとに新しい方。まだクラウドに書けていなかった手元の変更を失わない）
  - どれも言語（`lang`）は手元のものを残す
  - `session` が無い（この仕組みより前からログインしている）ときは、ログインしたままとして扱う。ログアウトの状態でページを開けば `out` になる
- 捨てた内容（習得状況・自分の手順・練習の記録のどれかが手元にあり、アカウントと違う。`Store.discardsLocal`。練習の記録は日時ごとに、秒・判定・ヒント・ペナルティを比べる）があれば、読み直したあとのページの下に知らせを出し（`.site-toast`。控えめな青で、出るときに少し大きくなって戻る（動きを減らす設定では動かさない）。× か 10 秒で閉じる）、「アカウントのデータを読み込みました。ログインする前にこのブラウザで使った内容は、アカウントのデータに置き換えました。」と知らせる（`sessionStorage` の `visualcube-editor:login-notice`）
- ログアウトのボタン：まだクラウドに書いていない変更を書いてからログアウトし、このブラウザのデータ（`Store` の全データ。言語だけ残す）を消して、ページを読み直す。読み直したあとは画面の下に「ログアウトしました。このブラウザのデータは消しました（アカウントには残っています）。」と知らせる
  - 書けなかったとき（オフラインで 15 秒以内に書けない・ログインの同期の途中）はログアウトせず、メニューに「最新の変更をアカウントに保存できなかったので、ログアウトしていません。…」と出す（消すと失うため）。記録を種類ごとの文書に書けず本体だけに書けたときは続ける
  - 同じブラウザのほかのタブには `visualcube-editor:signed-out-at` の `storage` イベントで伝え、読み直して空にする（画面に残っている古いデータを書き戻さないように）
  - ログインの期限切れ・ほかのタブでのログアウト・アカウントの削除など、ボタンを通らないログアウトではデータを消さない（アカウントの削除は、消すかを確認で選ぶ）
  - ページを開いたときの同期が失敗していたとき（`ready` が false のまま）は、まずログインの同期を読み直しなしでやり直す（15 秒まで）。できたら普段どおり書いてログアウトし、データを消す。やり直しても失敗したら（上限を超えた文書など、原因が続くもの）、ログアウトはするがこのブラウザのデータは消さず、`session` を `kept` にして、画面の下に「ログアウトしました。最新の変更をアカウントに保存できなかったので、このブラウザのデータは消さずに残しています。…」と知らせる。`kept` はログアウトの状態が分かっても `out` にしないので、次に同じアカウントで入るとログインしたままとして合わせる（保存できなかった変更を失わない）。別のアカウントなら持ち主が違うので持ち込まない
  - ほかのタブは `signed-out-at` を受けたら、すぐクラウドへの書き込みをやめて（`ready` を false、まとめて書く予定を消す）から読み直す。また、手元が言語だけのときはクラウドに書かない（ログイン中にそうなるのは、ほかのタブでログアウトしてデータを消した直後だけ。アカウントを空で上書きしないように）
  - 持ち主（`synced-uid`）は残す。次のログインは新しいログインとして、上の決め方でアカウントの内容を読み込む

## 合わせ方（`Store.merge`）
ログインしたままページを開いたときと、クラウドに書く前に同じアカウントの別の端末が書いていたと分かったときに使う（ログインしたときの上書きとは別）。
- 名前ごとに更新時刻の新しい方を使う（片方にしか無い名前は残す）
- `practice` は、両方にあれば練習の記録を合わせる（`mergePractice`。2 台で練習したときや、古いデータのままの端末で開いたときに、もう片方の記録を消さないように）
  - PLL・OLL・COLL・ZBLL の記録（`practice.log`）とソルブ・LL の記録（`practice.full.log`・`practice.ll.log`）：両方の記録を日時で 1 つにする（同じ日時は新しい方のもの）。消した記録の印（`removed`：種類ごとの日時の一覧、`cleared`：その日時以前はすべて消した）があるものは除き、種類ごとの上限（PLL・OLL・COLL・ZBLL 各 5000 件、ソルブ・LL 各 5000 件）で切る
  - 消した記録の印は `Store.set('practice', …)` が前の値との違いから付ける（`Store.withTombstones`。個別・選択・すべての削除、練習の結果の「取り消す」。上限で押し出された古い記録には付けない。「元に戻す」で戻したら外す。種類ごとに新しい 1000 件まで）。合わせるときは両方の印を合わせる
  - **VCE2 での違い**：`cleared` は、種類の記録がすべて消え、しかも消えた記録が 1 件ずつの印（1000 件）に入りきらないときだけ付ける。入りきるときは消えた記録にだけ印を付ける。移植元は種類の記録が空になれば必ず `cleared` を付けるので、その種類の記録が 1 件だけのときに「取り消す」と、まだ読んでいない別の端末のそれより前の記録まで消えてしまう
  - ケースごとの最近のタイム（`practice.times`。PLL・OLL・COLL・ZBLL）：合わせた記録から作り直す（ヒントなし・解けた回の新しい順に 10 回）。記録の方が少ないケース（記録を残す前の古いタイムなど）は新しい方のものを残す
  - それ以外（練習の設定・記録のページの表示など）は新しい方
- `progress`（習得状況）・`custom-algs`（自分の手順）は、両方にあればケースごとに、あとで変えた方を使う（`mergeCases`。2 台で練習・習得状況を変えたときに、片方の変更が消えないように）
  - 変えた時刻は `Store.set` が前の値との違いから、ケースごとに `_at: { pll: { Aa: 時刻 }, oll: { … } }` に付ける（`Store.withCaseStamps`）。未習得に戻した・既定の手順に戻した（値を消した）ケースにも付けるので、「すべて未習得に戻す」をした方があとなら、もう片方の古い習得済みで戻ってこない
  - 時刻が無いケース（この仕組みより前のデータ）は、新しく更新された方の値を使う（以前と同じ）
  - 読む側（`progress.js`・`custom-algs.js`・一覧・練習・記録など）は種類（`pll`・`oll`・`coll`・`zbll`）だけを見るので、`_at` は気にしなくてよい
  - ログインのときに捨てたか（`Store.discardsLocal`）を決めるときは `_at` を比べない（中身が同じなら捨てたことにならない）
- `Store.merge` の union（習得状況と自分の手順をケースごとに合わせる）は、ログインのときにはもう使わない

## 動き（`js/cloud-sync.js`）
- `js/firebase-config.js` の `window.FIREBASE_CONFIG` が `null`、または SDK を読み込めないときは何もしない（ログインのボタンも出さない）
- ログインしたとき・ログイン中にページを開いたとき：クラウドを読み → 上の決め方で手元に反映する内容を決め → 両方に書く。手元の内容が変わったらページを1回読み直して画面に反映する
  - 読み直す前に `sessionStorage` の `visualcube-editor:sync-reload` に時刻を残す。練習のページは、これが 30 秒以内なら読み直す前の問題（スクランブル）をそのまま出す（開いて 1 秒ほどでスクランブルが急に変わらないように。reference/PRACTICE_SPEC.md。MegaminxImageEditor 80685b1）
- ログイン中：`store-change` を受けて 1.5 秒まとめてからクラウドに書く。ページを離れる（非表示になる）ときは待たずに書く
  - 書く前に本体の文書を読み、最後に書いた（読んだ）中身と違えば、同じアカウントの別の端末が書いたので、クラウドを読んで `Store.merge` で手元と合わせてから書く（手元も合わせた内容にする。画面は次に開いたときに反映）。書き込みは 1 つずつ順番に
  - **VCE2 での違い**：練習の記録を足すときは、最近のタイムを保存したもの（`Store`）から読み直して足す（合わせた別の端末の最近のタイムを、ページを開いたときの古い値で上書きしないように。js/practice.js）
- 別の端末で変えた内容は、次にページを開いたときに反映される
- ログアウトのボタンでは、上のとおりこのブラウザのデータを消す

## 画面（全ページ共通のナビバー）
- ログイン前：言語の切り替えの右に、人のアイコン付きの濃い色のボタン **ログイン / Sign in**（角の丸い四角。マウスを乗せると少し浮く）。幅 992px 未満（スマホと、ナビバーのリンクが横に並ぶタブレット）では「ログイン」の文字を見た目だけ隠し、人のアイコンだけの 34px の四角いボタン（スマホのメニューのボタンと同じ大きさ）にする（文字があるとタイトルが「…」で切れるため。読み上げの名前は「ログイン」のまま）。あわせて、タブレット（768〜991px）ではナビバーのリンクの間を少し詰め、幅 360px 未満ではタイトルの文字を少し小さくして、どの幅（320〜1200px）でもタイトル「VisualCube Editor 3.0」を最後まで出す（css/common.css。MegaminxImageEditor 0a35649）。押すと Google・Facebook・GitHub のロゴ付きの「Google でログイン」「Facebook でログイン」「GitHub でログイン」のメニュー（よく使われる順）
- ログイン中：ナビバーにはアイコン（写真、無ければ名前の頭文字の丸）だけを出し、右下の小さな点で保存の状態を示す（緑＝保存済み、琥珀＝保存中で点滅、赤＝エラー。マウスを乗せると文で出る）
  - アイコンの右上に、ログインに使ったサービス（Google / GitHub / Facebook）のロゴを小さく出す。マウスを乗せると「Google でログイン中 · アカウントに保存済み」のように出る
  - アイコンを押すとメニュー：大きめのアイコン・名前・メールアドレス・「（ロゴ）GitHub でログイン中」、保存の状態（失敗したときはエラーの種類も）、**ログアウト**
- Facebook のプロフィール写真：Firebase が受け取る写真の URL はアクセストークンが無いと Facebook の既定の人型になるので、そのままは使わない。Facebook でログインした直後に、そのときのトークンで Graph API（`/me/picture`）から本人の写真の URL を受け取り、Firebase のプロフィールに保存する（トークンは保存しない）。写真の URL は Facebook 側で期限が切れるので、読めなくなったら頭文字の丸にする（次に Facebook でログインしたときに更新される）
- ページを開いたときのちらつきを防ぐ：ログイン状態が分かるまでは「ログイン」ボタンを出さない。前回ログインしていたときは、そのアカウントのアイコン・名前・ログイン方法を `visualcube-editor:account-hint` に覚えておき、ログイン状態が分かる前からアイコンを出しておく（分かるまではメニューは開かない。ログアウトしたら消す）
- メニューはメニューの外を押すか Esc で閉じる。ログインできなかったときはメニューの中にエラーを出す
- 同じメールアドレスのログイン方法をつなげる（アカウントのリンク）：Firebase の「同じメールアドレスを使用するアカウントをリンク」では、同じメールで別の方法を使うと `auth/account-exists-with-different-credential` になる（自動ではつながない）。このとき
  - 新しい方法の資格情報（`credentialFromError`）とメールアドレスをメモリに覚え、メニューに「{email} は別のログイン方法で登録されています。前に使った方法でログインすると、{provider} でもログインできるようにつなげます。」と、新しい方法以外のログインのボタンを出す（メールの列挙対策で、どの方法で登録したかは調べられないので本人に選んでもらう）
  - 前の方法でログインできて、メールアドレスが同じなら `linkWithCredential` で新しい方法をつなげ、「{provider} をつなげました」と出す。以後はどちらの方法でも同じアカウント（同じ uid・同じデータ）に入れる。メールアドレスが違えばつながずにそのままログインし、その旨を出す
  - ポップアップを閉じたときは覚えたまま。メニューを閉じる・ページを離れると捨てる（保存しない）

## Firebase の設定（サイトの管理者がやる）
プロジェクト・ログイン方法・Firestore は Megaminx Image Editor で設定済みのものをそのまま使う（手順は MegaminxImageEditor の `reference/CLOUD_SYNC_SPEC.md`）。
VisualCube Editor を公開するときに足すこと：

1. Authentication → 設定 → 承認済みドメインに `visualcube.roudai.net` を追加する（`localhost` は最初から入っている）
2. Firestore の「ルール」が、`appIds()` に `visualcube-editor` を含む版（このリポジトリの `firestore.rules`）になっているか確かめ、違えば貼って公開する。
   古い版のままだと `users/{uid}/apps/visualcube-editor` を作れず、保存の状態が赤（エラー）になる
3. Google / GitHub / Facebook のリダイレクト URI は Firebase の `https://<project-id>.firebaseapp.com/__/auth/handler` のままなので、追加は要らない見込み（未確認）
4. Facebook アプリ（開発者サイト）の「アプリドメイン」「ウェブサイト」に `visualcube.roudai.net` を足す必要があるか、アプリが「ライブ」かは未確認
5. 公開したサイトで、3つの方法のログイン・同じメールのアカウントのリンク・データの削除を確かめる

公開（`main` へのマージ）で自動的にサイトが更新される場合は、1・2 が済むまでマージしない（ログインのボタンは出るのに、ログインや保存が失敗する状態で公開されるため）。
